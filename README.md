# AI-eat · AI 菜谱助手

AI-eat 是一个部署在局域网的自用 Web 工具：用本地 JSON 文件管理自己的菜谱库，并接入 OpenAI 兼容的大模型接口，实现 AI 聊天推荐菜谱、按现有食材「点菜」生成一桌菜单、AI 估算营养等能力。移动端优先设计，深色模式跟随系统。

## 功能清单

- **问问AI（首页 `/`）**：说说冰箱里有什么，AI 按食材自然搭配出推荐清单（每种食材都有用途，能合并成一道菜就合并），确认后逐菜生成完整菜谱；说「继续」只追加未推荐过的新菜。SSE 流式，聊天记录不持久化（刷新即丢）
- **菜谱库（`/recipes`）**：搜索（防抖）、标签筛选（按频次降序、随分类收敛、单行横滑）、格式异常文件提示、空态引导；右下角浮动按钮录入新菜谱
- **菜谱详情（`/recipes/[id]`）**：查看 / 编辑 / 删除；营养四项 + AI 估算值标注；食材表、步骤有序列表
- **人工录入 / 编辑（`/recipes/new` 等）**：受控表单，食材/步骤可增删行；「AI 生成」按菜名回填整份菜谱、或单独「AI 估算营养」回填四项
- **买什么（`/dishes`）**：两段式——输入人数（+ 可选口味偏好）生成一桌菜单与采购建议，看中哪道再单独生成完整菜谱并入库
- **访问记录（`/access-logs`）**：写操作、AI 调用、登录尝试等敏感操作审计（时间/IP/方法/路径/状态码/操作者），50 条一页，最多保留 200 条；仅管理员可见
- **备份（`/settings`）**：成员导出/导入自己的菜谱；管理员额外可导出全部用户（不含凭据）。整机恢复请备份 `data/` 目录
- **多用户与鉴权（可选）**：`PASSWORD` 非空=密码模式（管理员用「用户名 + 本值」登录，管理员密码只取环境变量；可创建/禁用/删除成员，每人的菜谱库与推荐风格独立）；`PASSWORD` 空=免密单用户（自动使用最早的管理员「管理员」，其他账号冻结但数据保留，用户管理关闭）。`DELETE_ENABLED` + `DELETE_PASSWORD` 另提供删除密码校验
- **移动端与深色模式**：375px 宽无横向滚动、触摸目标 ≥44px、输入字号 16px（防 iOS 聚焦缩放）；深色模式跟随系统（`prefers-color-scheme`），无手动切换

## 快速开始

### 方式一：裸机（需 Node.js 20+）

```bash
# 1. 安装依赖
npm ci

# 2. 配置环境变量（全部可选，见下表）
cp .env.example .env
vim .env

# 3. 构建 + 后台启动（默认端口 8888，可用 PORT=xxx 覆盖）
./run.sh

# 其他命令
./run.sh status    # 查看运行状态
./run.sh restart   # 停止 + 清构建产物重新构建启动（改代码后用它）
./run.sh stop      # 停止
```

启动成功后会打印本机与局域网访问地址；日志在 `ai-eat.log`。

### 方式二：Docker Compose

```bash
# 1. 配置环境变量（compose 自动读取同目录 .env）
cp .env.example .env
vim .env

# 2. 先创建数据目录（必须由当前用户创建，见下方「数据目录归属」）
mkdir -p ./data

# 3. 构建并启动（宿主机 8888 → 容器 3000，数据落宿主机 ./data）
docker compose up -d

# 查看日志 / 停止
docker compose logs -f
docker compose down
```

**数据目录归属（务必读）**：compose 用 bind mount `./data:/app/data`，容器内以 `node`（uid 1000）运行，
因此**宿主机 `./data` 的属主必须是 uid 1000**。`data/` 在 `.gitignore` 里，新克隆默认不存在——
若不加上面的 `mkdir -p ./data` 直接 `docker compose up`，docker daemon 会以 `root:root` 创建该目录，
容器内写不进去，表现为「保存菜谱/改设置全部 500」且审计日志静默丢失（`appendAccessLog` 吞异常）。

排查：`stat -c %u ./data` 应等于 **1000**（容器内 `node` 的 uid）。
即使 `ls -ld` 显示的是「你自己的用户」也不一定正确——若你的 uid 不是 1000（部分发行版/企业镜像的首用户是 1001），
容器仍写不进去。此时执行 `sudo chown -R 1000:1000 ./data`；或在 `docker-compose.yml` 的 service 下加
`user: "1000:1000"` 让容器以该 uid 运行（不依赖宿主机 chown，更稳）。

## 环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `AI_BASE_URL` | 否 | AI 供应商 OpenAI 兼容接口地址（如 `https://api.example.com/v1`） |
| `AI_API_KEY` | 否 | AI 供应商 API Key，仅服务端读取，任何接口不会回显 |
| `AI_MODEL` | 否 | 模型名（按供应商填写，如 `deepseek-chat`） |
| `AI_TEMP_CHAT` / `AI_TEMP_MENU` / `AI_TEMP_RECIPE` / `AI_TEMP_NUTRITION` | 否 | AI 温度分层覆盖：默认 0.7 / 0.8 / 0.7 / 0.5；非法值自动回落并限制在 0~1 |
| `PASSWORD` | 否 | **运行模式开关**：非空=密码模式（管理员用「用户名 + 本值」登录，管理员密码只取本值；可创建/管理成员）；空=免密单用户（自动创建或使用最早的管理员「管理员」，其他账号冻结但数据保留，用户管理关闭）。改后必须重启进程 |
| `SESSION_SECRET` | 否 | 会话签名密钥。建议显式设置（≥32 字符）；不设则首次运行自动生成 `data/.session-secret`（0600）。更换/删除会使全部已登录会话立即失效 |
| `TRUST_PROXY` | 否 | 仅在前置可信反代终结 TLS 时设为 `true`。影响两处：访问记录 IP，以及登录失败限流分桶——不设时所有直连客户端共享同一个限流桶（防伪造 `X-Forwarded-For` 绕过），设为 `true` 才按真实客户端 IP 分桶 |
| `DELETE_ENABLED` + `DELETE_PASSWORD` | 否 | 两者同时满足时启用删除密码保护（全局同一口令，服务端恒时校验） |
| `AI_EAT_DATA_DIR` | 否 | 菜谱库目录（默认 `<项目目录>/data/recipes`）。其**父目录即数据根**：`users.json`、`users/`、`logs/`、`.session-secret` 都落在父目录。多用户模式下实际库在 `<数据根>/users/<uid>/recipes`，本变量只在首次建号接管旧数据时作为旧库来源。裸机无需设置，Docker 由 compose 注入 |

三项 AI 配置（`AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL`）齐备时 AI 功能可用；缺省时应用仍可正常使用手动菜谱、备份等本地功能，仅 AI 生成与点菜不可用。设置页（`/settings`）可查看当前配置状态。

## 备份说明

数据全部为本地 JSON 文件，无数据库。**备份包含账号表（scrypt 哈希）与会话签名密钥，请按敏感文件保管。**

1. **目录备份（推荐，唯一可整机恢复的通道）**：停机后整目录复制 `data/`（裸机 `<项目目录>/data`；Docker 宿主机 `./data`）。它包含 `users.json`、`users/<uid>/`（每人的菜谱与推荐风格）、`logs/access.jsonl`、`.session-secret`。恢复后旧会话仍有效；如需让所有会话立即失效，删除 `.session-secret` 再启动。
2. **页面导入导出（只处理菜谱）**：
   - 成员导出自己的库 `{ exportedAt, recipes }`；管理员导出 `{ exportedAt, recipes（自己的库）, users: [{ name, recipes }] }`（全部用户，不含密码/会话密钥）。
   - 导入**永远只写当前账号自己的库**（按 id 跳过已存在、非法条目跳过），不恢复账号、他人菜谱、推荐风格与会话密钥。
   - 上限：请求体 5MB、最多 5000 条；超限分别返回 413 / 400。
   - 因此管理员的全量导出**不能**通过页面导入做整机恢复——请使用目录备份。

## 局域网访问

启动后同一局域网内的手机/平板直接访问：

```
http://<服务器IP>:8888
```

服务器 IP 可用 `./run.sh status` 查看。**建议首次启动前就在 `.env` 设置 `PASSWORD`**：不设置即免密单用户，局域网内任何人访问都以管理员身份操作；设置后为密码模式（管理员 + 成员），首次打开 `/login` 用「用户名 + PASSWORD」初始化管理员。

## 已知限制

- **AI 生成内容未经核实**：AI 菜谱与点菜结果为模型生成内容，未经联网核实，食材用量、步骤、时长等请自行判断；过敏原、食品安全相关请务必自行确认。
- **营养为估算值**：营养四项（热量/蛋白质/脂肪/碳水）为 AI 估算，非实测，仅供参考，不作为健康或医疗依据。
- **聊天记录不持久化**：AI 聊天仅存内存，刷新页面即丢失（有意设计）；需要保留的菜谱请及时「存入菜谱库」。
- **Docker 真实构建验收待补验**：Dockerfile 三段构建、compose 编排已就绪，但开发环境无 Docker，真实 `docker compose up` 构建验收待有 Docker 环境时补验一次（裸机 `run.sh` 路径已实测）。
