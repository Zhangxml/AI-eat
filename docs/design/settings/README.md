# 用户设置（/api/settings，按用户隔离）

> 一句话：每个账号有独立的**可写**偏好（目前是推荐风格），存 `data/users/<uid>/settings.json`，服务端直接消费（前端不传参）。

## 为什么有这一层

推荐风格（湖北家常 / 换换口味）最初是页面内 `state`，随请求以 `?style=` / body 字段传给 AI 路由。这带来三个问题：

| 问题 | 后果 |
| --- | --- |
| 页面 state 不持久 | 刷新即回默认，用户每次都要重选 |
| 多设备各存各的 | 手机设为湖北家常、平板仍是换口味 |
| 同一概念两种传法 | chat 用 query、menu/recipes 用 body，契约不一致 |

既然是**服务端持久化**的偏好，服务端本来就知道答案，不该反过来等前端告诉它。改造后：

```
data/users/<uid>/settings.json  ← 持久层（按用户隔离，同受 data 卷保护）
        ↑
src/lib/settings.ts       ← zod schema + 默认值 + 合并（唯一事实来源）
        ↑
src/lib/settings-store.ts ← 读（容错回落默认）/ 原子写
        ↑
GET/PATCH /api/settings   ← 鉴权 + 体积闸门 + strict 校验 + 访问日志
        ↑
设置页（可编辑）  /  AI 路由（readSettings 直接读）
```

**前端不再传 style**：`/api/ai/chat`、`/api/ai/menu`、`/api/ai/recipes` 各自 `readSettings()`。即使有人绕过 UI 直接调接口，行为也与设置页一致。

## 数据结构

```json
{ "version": 1, "style": "home" }
```

- `version`：当前恒为 1，为未来字段改名/结构迁移留口；**读取时恒由服务端覆写为当前版本**（不采信文件里的值）
- `style`：`home`（**湖北家常**，默认）| `creative`（外省中式创意换口味）

### 读取宽松、写入严格（Postel 原则）

这是为「后续还会加设置项」预留的关键设计。若读取时要求文件**完全合法**（字段齐全、无多余键），
那么以后一旦新增字段，老用户的文件必然缺字段 → 整体校验失败 → **已调好的设置被静默重置为默认**。

因此两侧口径不同：

| 环节 | 口径 | 行为 |
| --- | --- | --- |
| 读取文件 `parseSettingsFile` | **宽松** | 缺字段 / 未知键 / 未来版本多写的字段 → 忽略，**认得的值全部保留**；字段值非法 → 该字段回落默认；非对象/数组 → 全默认 |
| PATCH 请求体 `validateSettingsPatch` | **严格**（strict） | 未知键 400（防拼写错误被静默吞掉）、非法值 400 |
| 写入前 `writeSettings` | **严格**（schema.parse） | 兜住「未来代码传非法值」的内部 bug，坏数据不落盘 |

实测（`parseSettingsFile` 输入 → 结果）：

```
{version:1, style:'creative'}                → style=creative   正常
{style:'creative'}                           → style=creative   缺 version 仍保留
{version:2, style:'creative', servings:4}    → style=creative   未来版本多字段仍保留
{version:1, style:'creative', foo:'bar'}     → style=creative   垃圾键忽略
{version:1, style:'exotic'}                  → style=home       非法值才回落
null / [1,2] / 'oops'                        → style=home       非对象全默认
```

文件损坏（JSON 解析失败）或不存在 → 默认 `{ version: 1, style: 'home' }`，**绝不崩**（设置坏了不能把整个应用带下去）。

## API 契约

| 方法 | 路径 | 成功 | 失败 |
| --- | --- | --- | --- |
| GET | `/api/settings` | `200 Settings` | `401`（启用 PASSWORD 且无会话） |
| PATCH | `/api/settings` | `200 Settings`（合并后的完整设置） | `400 { error }`（未知键/非法值/非 JSON）、`401`、`500 { error }`（写盘失败） |

**为什么 PATCH 而不是 PUT**：局部更新语义——以后加字段时，老客户端只传自己知道的键，不会把新字段覆盖成空。

**strict 校验**：`{ stlye: 'creative' }`（拼错）→ 400 明确报错，不静默吞掉。否则用户以为改了，实际没改。

## 与 /api/config 的边界

| 接口 | 性质 | 来源 | 内容 |
| --- | --- | --- | --- |
| `/api/config` | 部署级、**只读** | 环境变量 | AI 是否配置、baseUrl/model、鉴权/删除保护开关（页面只展示 model，不展示 baseUrl） |
| `/api/settings` | 用户级、**可写** | `data/users/<uid>/settings.json` | 推荐风格等偏好 |

两者不重叠：env 决定「能不能用」，settings 决定「怎么用」。**优先级约定：用户设置 > 环境变量 > 代码默认**（本次 style 无 env，只实现「文件 > 默认」）。

## 容错与边界

| 场景 | 行为 |
| --- | --- |
| 设置文件不存在 | 默认 home |
| 文件是坏 JSON / 字段非法 | 默认 home（读取层 `try/catch` + zod 校验） |
| 目录不存在（首次写） | `mkdir -p` 自动创建 |
| 写盘中途失败 | 临时文件 + rename 原子替换，残留 tmp 清理；API 映射 500 中文提示 |
| 两台设备同时改 | 后写覆盖（单人自用可接受） |
| 未启用 PASSWORD | 守卫放行，零摩擦 |
| Docker 部署 | `data/` 已挂卷，无额外配置 |
| 备份 | 目录直备天然包含每人的 `settings.json`；页面导出/导入仍**只导菜谱**（不扩大备份契约，换机时设置需重设） |

## 加一项新设置要改哪里

1. `src/lib/settings.ts`：schema 加字段 + 默认值 + `mergeSettings` 合流 + **`parseSettingsFile` 补该字段的宽松解析**（漏了这步，老文件里的新字段永远读不到）
2. `src/lib/settings-store.ts`：通常不用改（整对象读写）
3. `src/app/api/settings/route.ts`：错误文案里的字段清单
4. 设置页：加一组 UI（`changeStyle` 同款乐观更新 + 失败回滚）
5. 消费点：需要的地方 `readSettings()`

后续候选：默认份量、忌口/过敏原、是否显示营养、温度覆盖、模型切换。**注意**：API Key 永远只能来自 env，**绝不下发/不落盘明文**。

## 页面：AI 供应商只读展示

只显示 **模型名**（如 `deepseek-v4-flash`），**不显示接口地址**（`baseUrl`）。

- 接口地址对使用者没有决策价值（改不改都得改服务端 env），反而占一行、暴露部署细节
- 接口地址**不是密钥**，`/api/config` 仍返回该字段（非敏感、便于排障），只是页面不渲染
- **这是展示精简，不是安全措施**：未启用 `PASSWORD` 时，局域网内 `curl /api/config` 仍能读到 `baseUrl`。要收口请启用 `PASSWORD`（该接口受 `requireAuth` 保护）
- 密钥（`AI_API_KEY`）任何时候都不出现在任何响应里（红线测试锁定）

## 页面：隐藏的「访问记录」入口

设置页底部的「访问记录」入口**默认隐藏**，在「访问鉴权」卡片上**连点 5 次**才出现；刷新页面或离开后重进一律回到隐藏。

### 为什么用内存态，不用任何持久化

需求里的「刷新后隐藏」直接排除了所有持久化方案：

| 方案 | 刷新后隐藏 | 结论 |
| --- | --- | --- |
| 组件内存态（选定） | ✅ | 唯一满足 |
| `sessionStorage` | ❌ 同标签页刷新仍在 | 不满足 |
| URL 参数 `?logs=1` | ❌ 刷新保留 | 不满足 |
| 写进 `data/users/<uid>/settings.json` | ❌ 反而永久保留 + 同一账号多设备同步 | 反向 |

### 「连续」的定义

相邻两次点击间隔 **≤ 1.5 秒**才算连续；一旦超过就从这一下重新计数（防「昨天点 3 次、今天点 2 次」误触发）。达到 5 次后保持显示，无需继续点击。逻辑抽在 `src/lib/tap-reveal.ts`（`createTapReveal`，可注入时间源），有 16 条单测锁定边界（含「恰好等于窗口算连续」「超 1 毫秒即重置」「达阈值后不回落」「非法时间戳按 0 处理」「小数阈值向下取整」「NaN/Infinity 参数回落默认」「时钟回拨不算连续」「windowMs=0 边界」「传 null 不抛错」「默认值已冻结」）。

设置页本身是纯 UI 页、项目无组件测试，所以把计数逻辑抽成纯对象是唯一能测的做法。

### 交互细节

- **整张「访问鉴权」卡片可点**（`role="button"` + `tabIndex=0` + Enter/Space），手机上更容易连点
- **刻意不做任何进度提示**——否则点到第 3 次就被旁人看出端倪，隐藏失去意义；只保留 `active:bg-neutral-50` 按压反馈
- **圆角联动**：「访问鉴权 / 删除保护 / 访问记录」是连体分组（首卡顶部圆角、尾卡底部圆角）。入口隐藏时「删除保护」成为组尾，需切换为 `rounded-b-xl` + 有下边框，否则页面底部会缺圆角、多一条断边
- **进出都用 `replace`**：设置 → 访问记录、以及从访问记录经底部导航离开，都不新增历史项而是替换当前项。
  否则知情者用过一次后，不知情的人按**浏览器后退**就能直接落到访问记录页，绕开连点手势（实测复现过）。
- **隐藏页保留底部导航，但离开时用 `replace`**：`/access-logs` 本身不属于四个 tab，页内也不再放「返回设置」按钮
  （原实现放了一个，现已移除），出口交给底部导航。为避免「点 tab 离开」把隐藏页 push 回历史栈
  （审查实测到的第二条泄漏路径），`BottomNav` 在该路由下给所有 tab 加 `replace`。
  同时把「设置」tab 点亮，表示当前处于设置层级——否则四个 tab 全不高亮，用户会疑惑「我在哪」。
- 页头只保留标题 + 「刷新」按钮；该按钮与菜谱库「分类 / 标签」chips 同规格：**32px 高、`rounded-md`（6px）、`px-3`、1px `neutral-300` 边框**（页头只有这一个轻量控件，统一更整齐；32px 仍高于 WCAG 2.5.8 的 24px 下限，主操作按钮仍为 44px 档）。
- 直接访问 `/access-logs` 网址**仍可打开**——入口隐藏不等于访问控制（见下）

### chip 规格

「推荐风格」两个 chip 与菜谱库筛选 chips 同规格：**32px 高 + `rounded-md`（6px 圆角）**。
早期用 `rounded-full` 胶囊，视觉上显得又高又圆，与卡片内其他控件不协调（用户反馈后统一收紧）。

焦点环显式声明 `focus-visible:outline-2 outline-offset-2`：UA 默认环取 `currentColor`，
选中 chip 的文字与底色互为反色，环会被同色吃掉；过渡属性也显式列出（不含 `outline-color`），
否则焦点环会从 `currentColor` 渐变过去、聚焦瞬间不可见。

### 这不是权限控制

本功能的定位是「**给特定人群用的隐藏功能**」：知道连点手势的人能用，随手翻设置页的人看不到。

已在实现层面堵住的绕过路径：

| 路径 | 状态 |
| --- | --- |
| 随手翻设置页看到入口 | 已隐藏（默认不渲染，也不预取——实测解锁前 0 条 `/access-logs` 的 `_rsc` 请求） |
| 经底部导航离开后按后退 | 已堵（`replace`，历史项被替换而非新增） |
| 多次往返累积历史 | 已堵（实测 3 轮往返 `history.length` 不变） |
| 刷新或离开后残留 | 无（纯内存态，无 localStorage/sessionStorage 痕迹） |
| 用浏览器「后退」键离开该页后的**前进栈** | ⚠️ **固有限制**：前进仍可回到该页，除非清空浏览器历史（代价过大）。经底部导航（`replace`）离开就不会留痕 |
| 启用 PASSWORD 且会话失效时 401 跳登录 | ⚠️ **边界**：`apiFetch` 的 401 跳转是整页跳转，会在历史里新增一条，后退可回到该页外壳（数据仍受 401 保护）。当前部署未启用 PASSWORD，故未触发；要彻底消除需把 `apiFetch` 改成 `location.replace('/login')`（影响全站 20 处调用、8 个文件，宜单独立项） |
| 直接输入 `/access-logs` 网址 | **仍可打开**（不使用手势的第二条入口，属已知边界）。从书签打开后经底部导航离开是 `replace`，会把书签那条历史项替换掉——之后后退会直接离开站点，属同一取舍的延伸 |
| 用浏览器「前进」回到该页 | ⚠️ 同「前进栈」固有限制（用后退键离开时前进栈保留该页） |

要拦「知道网址的人」，只能启用 `PASSWORD`（之后 `/api/access-logs` 返回 401）。代价是每次访问都要输口令，与「隐藏功能」的轻量定位不同——按需取舍。
