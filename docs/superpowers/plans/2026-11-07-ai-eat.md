# AI-eat 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 构建「AI 菜谱」自用工具：对话式 AI 生成菜谱/点菜 + 服务端文件菜谱库，Next.js 全栈单体，手机浏览器访问，局域网部署。

**架构：** Next.js 15（App Router）+ React + TypeScript 单进程；API Routes 承担 AI 代理（OpenAI 兼容，SSE 流式）与菜谱库文件 CRUD（`data/recipes/*.json` 一菜一文件）；UI 为移动端优先响应式网页（Tailwind CSS v4），底部 Tab 导航。

**技术栈：** Next.js 15、React 19、TypeScript（strict）、Tailwind CSS v4、zod 3（运行时校验）、vitest 3（node 环境）、Node 20+。

**规格：** `docs/superpowers/specs/2026-11-07-ai-eat-design.md`（本计划依据该规格，两者需一起阅读）。

## 全局约束

- 菜谱数据一律存服务端 `data/recipes/<id>.json`，**禁止任何浏览器持久化**（IndexedDB/localStorage 均不允许）
- AI API Key 只在服务端进程内读取环境变量，**不进浏览器**；所有 AI 请求经 `/api/ai/*` 代理
- 数据目录可测试注入：`recipesDir()` 返回 `process.env.AI_EAT_DATA_DIR || path.join(process.cwd(), 'data', 'recipes')`
- AI 供应商配置（OpenAI 兼容）：`AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` 三个环境变量缺一不可，缺失时报中文错误
- AI 结构化输出必须经 zod 校验；解析失败重试一次，仍失败则报错，**不得把脏数据入库**
- SSE 事件协议（聊天）：`message`（正文增量）/ `recipe`（完整结构化菜谱 JSON）/ `error`（错误）/ `done`（收尾）
- 端口约定：裸机 `PORT` 默认 8080；Docker 容器内 3000、宿主机映射 8080
- 界面移动端优先：单列布局、触摸目标 ≥ 44px、无横向滚动；所有新增代码注释用中文
- 测试框架 vitest（node 环境，不引入 jsdom）；lib 层与 route handler 必须有测试，纯 UI 页面手工验收
- 测试临时目录统一放 `/tmp/opencode` 下
- 每个任务结束时提交一次 git；仓库根即 `~/tools/AI-eat`

## Review Focus（规格隐含、易咬人的失败模式）

1. **浏览器清缓存/换设备后菜谱库丢失** —— 用户明确否定过的反目标。期望：数据只在服务端文件。→ Task 3 测试 `create 后从新实例 list 仍在`（重新 import + 新临时目录断言磁盘文件存在）；Task 4 测试走 API 全链路落盘。
2. **AI 输出格式异常**（前后杂文本、`<recipe>` 标签包裹、字段缺失/类型错）—— 期望：提取+校验，失败重试一次，仍失败报中文错误不入库。→ Task 9 `extractRecipeJson` 各形态用例；Task 10 「两次失败返回 502 且不写文件」。
3. **用户手改 `data/recipes/` 留下非法 JSON** —— 期望：列表跳过并在 `invalidFiles` 上报，服务不崩。→ Task 3 专门用例。
4. **AI 环境变量未配置** —— 期望：`/api/ai/*` 返回 503 + 中文提示，进程不崩。→ Task 8 `loadAiConfig` 抛错用例；Task 10/11/13 各一条 503 用例。
5. **PASSWORD 启用后未带会话的请求** —— 期望：读接口与写接口一律 401；未设置 PASSWORD 时全放行。→ Task 16 逐路由 401 用例。
