# 「家常」档改为「湖北家常」（设计）

> 日期：2026-11-09
> 范围：提示词与灵感词池（`ai-prompts.ts`、`menu/route.ts`、`inspiration.ts`）+ 设置页文案
> 状态：已确认方案 B + B1，待实施

## 意图

默认档位 `home` 的语义从「全国家常菜（番茄炒蛋、青椒肉丝）」改为「**湖北家常菜**」。用户人在湖北，本地食材都能买到，希望日常推荐就是湖北口味与做法，而不是通用家常菜。

`creative`（换换口味）**保持全国**（川/粤/湘/江浙/西北/东北）：语义自洽——跳出湖北吃外省。

## 非目标

- 不改 `style` 枚举值（`home` / `creative`）——改了会让 `data/settings.json` 里的 `home` 失效，要写迁移
- 不改 API 契约、SSE 协议、schema、存储
- 不做「湖北招牌菜清单」硬编码（会重新收敛输出，回到「同食材总出同几道菜」的老问题）

## 方案（已选定 B + B1）

**决策倾向改「做法与味型」，不硬塞菜名清单。**

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| 人设首句 | 中餐家常菜 AI 菜谱助手（两档共用） | home → **湖北家常菜** AI 菜谱助手；creative → 中餐家常菜（保持） |
| 人设档位句 | 优先**经典家常做法**：简单易做、食材好买、好吃下饭 | 优先**湖北家常做法**：粉蒸、煨汤、腊味小炒、藕与鱼鲜都常见，口味咸鲜微辣；做法简单、食材好买、好吃下饭 |
| 聊聊AI 清单做法规则 | 优先给**家常经典做法**（番茄炒蛋、番茄蛋汤） | 优先给**湖北家常做法**（粉蒸肉、排骨藕汤、腊肉炒菜薹） |
| 买什么档位句 | 菜品以**经典家常菜**为主 | 菜品以**湖北家常菜**为主：多用粉蒸、煨汤、腊味，常见藕与鱼鲜 |
| 灵感技法池（home） | 小炒/炖煮/清蒸/凉拌/红烧/焖/煎/汆烫 | 粉蒸/煨汤/腊味/干炕/蒸菜/红烧/小炒/凉拌 |
| 灵感风味池（home） | 下饭/清淡/汤水足/面食/快手/家常味 | 咸鲜/微辣/腊香/湖鲜/汤水足/酱香 |
| 设置页 chip | 家常 | 湖北家常 |
| 设置页说明 | 经典家常菜优先：做法简单、食材好买、下饭 | 湖北家常菜优先：粉蒸、煨汤、腊味、藕与鱼鲜，做法简单下饭 |

### 为什么词池这样选

- **技法**取湖北真正高频的：粉蒸（沔阳三蒸一路）、煨汤（排骨藕汤/瓦罐鸡汤）、腊味（腊肉炒菜薹）、炕（炕土豆/炕豆腐/炕豆丝）、蒸菜（天门蒸菜）。去掉「炖煮/焖/煎/汆烫」这类过于中性的词——首版只换词不换这类中性词时，实测湖北特征命中率仅 **9%**。
- **风味**取湖北辨识度最高的：咸鲜、微辣（湖北是微辣不是重辣）、腊香、湖鲜（千湖之省）、汤水足、酱香。
- **与 creative 池零重叠**：creative 的技法（干煸/砂锅/椒麻/蒜香/糖醋/酱烧/白灼/锅塌）与风味（川味/粤式/湘味/江浙/西北/东北）都不出现在 home 池，现有测试「home 输出不含 creative 词」继续成立。
- 用户已确认本地能买到藕、腊味、鱼鲜，因此提示词可以点名它们，不需要为「食材好买」妥协到只写技法。

## 实测（真实调用 DeepSeek，非估算）

判定口径：菜名含湖北特征词（藕/腊/粉蒸/煨/炕/蒸菜/糍粑/鱼糕/菜薹/豆丝/汆汤/热干面/豆皮/洪山）。

| 版本 | 场景 | 湖北特征命中 |
| --- | --- | --- |
| 仅换文案与中性词池 | 问问AI（4 组食材 × 2 次） | **9%**（1/11） |
| 加入「食材→湖北做法」映射 | 问问AI（4 组食材 × 2 次） | **50%**（5/10） |
| 最终版 | 买什么 home × 3（各 5 道） | **73%**（11/15） |
| 最终版 | 买什么 creative × 3 | **8%**（1/13，且是湘式腊肠焖饭，不属湖北） |

典型 home 输出：`莲藕排骨汤 / 腊肉炒红菜薹 / 粉蒸茼蒿 / 炕豆腐 / 粉蒸肉（南瓜垫底） / 炕土豆`。

典型 creative 输出：`蒜泥白肉 / 擂辣椒蒜香茄子 / 紫苏煎黄瓜 / 剁椒腊肠焖饭`（外省，未被湖北带走）。

**未命中的合理情况**：番茄+鸡蛋这类食材本身没有湖北专属做法（湖北家庭做番茄炒蛋与全国一致），命中率低是正常的，不应为此硬造「湖北版番茄炒蛋」。

## review 发现的回归：同食材收敛

首版提示词写的是「**优先选湖北做法而不是通用做法**」+ 硬映射（土豆→炕土豆/粉蒸…）。实测同一输入跑 4 次：

| 食材 | 修复前 | 修复后 |
| --- | --- | --- |
| 土豆 + 青椒 | 4/4 全是「青椒炕土豆」的变体 | 唯一菜数 4/6，出现炕、粉蒸、凉拌酸辣土豆丝 |
| 五花肉 + 土豆 | 4/4 全是粉蒸/炕土豆 | 唯一菜数 5/6，出现红烧肉、干炕片炒、粉蒸 |
| 豆腐 + 青菜 | 4/4 全是炕豆腐 | 唯一菜数 5/6，出现煨汤、烧豆腐、粉蒸豆腐 |

这正是当初「同食材总出同几道菜」的老问题复发。修法（改的是措辞，不是加规则）：

- 把「优先选湖北做法而不是通用做法」弱化为「能做成湖北风味就优先湖北风味」
- 映射后补「**但不要每次都套用同一种：同一食材有多种湖北做法时请轮换**（土豆也可红烧、煨汤、小炒；豆腐也可煨汤、家常烧；五花肉也可红烧、小炒）」

修复后湖北命中率仍为 **69%**（买什么 × 3），creative 档 8%，未被污染。

## 措辞上的三条硬约束（review 后补）

1. 映射必须写成「**可参考**…同一食材也可换用别的湖北做法」——早期写成绝对映射会让土豆永远变炕土豆，重蹈「同食材总出同几道菜」
2. 必须声明「**若用户已明确指定菜名，以用户菜名为准**」——`systemPromptWithLibrary` 同时服务 `/api/ai/recipes` 的指定菜名路径，否则用户点「麻婆豆腐」会被提示词往炕豆腐带
3. 只用湖北真正有辨识度的对应：豆腐→炕豆腐（「家常豆腐」是通用/川湘，不具湖北特征）、鱼→糍粑鱼/汆汤（湖北的「煨汤」主要指排骨藕汤/瓦罐鸡汤，不是鱼）
